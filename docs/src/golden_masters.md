# Golden-Master Cross-Validation (xAct)

TensorGR ships with a cross-platform golden-master suite that uses
[xAct](http://www.xact.es/) (Mathematica, via `wolframscript`) as an
independent ground-truth oracle. Committed JSON files under
`test/golden/data/` are authoritative. Consumers in
`test/golden/consumers/` are pure Julia; CI has no Wolfram dependency.

Full plan, conventions, and issue tracking: `test/golden/PLAN.md`,
`test/golden/CONVENTIONS.md`, and the `TGR-bhs5` epic in beads.

## Running the golden tests

The golden suite is gated behind an environment variable so the default
`Pkg.test()` run stays fast:

```bash
# Run only the golden tests (bypass the main suite):
julia --project=test test/test_golden.jl

# Run the full suite AND the goldens:
TENSORGR_GOLDEN=1 julia --project -e 'using Pkg; Pkg.test()'
```

## Regenerating the golden JSON files

Each case is generated by a `.wl` script under `test/golden/generators/`.
The `regen.jl` driver runs them all via `wolframscript`:

```bash
# Dry run — list generators that would run:
julia --project test/golden/regen.jl --dry-run

# Regenerate everything:
julia --project test/golden/regen.jl

# Regenerate a single case:
julia --project test/golden/regen.jl bianchi
```

**Prerequisites:**
- `wolframscript` on `PATH` (ships with Mathematica ≥ 11).
- A working Wolfram license (e.g. license-server line in
  `/usr/local/Wolfram/Wolfram/<ver>/Configuration/Licensing/mathpass`).
- xAct sources at `reference/xAct/xAct/` (already in this repo).

The generators auto-add `reference/xAct/xAct/` to `$Path`, so no xAct
install is required.

## Adding a new case

1. Write `test/golden/generators/<name>.wl`. Start from an existing
   generator (e.g. `kretschmann.wl`) and copy the `caseFile` skeleton.
2. Run it: `wolframscript -f test/golden/generators/<name>.wl`. This
   writes `test/golden/data/<name>.json`.
3. Run the suite: `julia --project=test test/test_golden.jl`.
4. If the case requires a new op (not `:simplify`/`:to_riemann`/...), add
   an entry to `OP_DISPATCH` in `test/golden/consumers/golden_runner.jl`.

## Investigating a golden failure

When `test_golden.jl` fails, the runner prints a JSON diff showing the
expected vs. got canonical forms. Per the plan's hard rules:

> Physics is ground truth, not pinned numbers. A golden that disagrees
> with physical identity takes precedence over any committed `.json`.
> Investigate the JSON, do not silence the test.

Common causes:
- xAct and TensorGR tie-break the Butler-Portugal canonical form
  differently. Regenerate the JSON and inspect; if both forms are
  mathematically equivalent, the regenerated JSON is authoritative.
- A real regression in TensorGR's `simplify` or a basis-conversion op.
  Open a bug, fix the core module, don't touch the golden.
- A new xAct version changed its canonical form. Regenerate, commit.

## Known limitations

- xPert-based curvature perturbation cases (TGR-bhs5.21..25) are
  blocked pending investigation of why `DefMetricPerturbation`
  doesn't register `ExpandPerturbation1` downvalues for
  `RicciCD`/`RiemannCD` in our runtime, even though metric
  perturbations work correctly.
- xAct's `ToCanonical` in standalone form (no surrounding product
  context) sometimes emits `ToCanonical::noident` warnings but leaves
  expressions unchanged. These tests still act as regression guards
  for TensorGR.
