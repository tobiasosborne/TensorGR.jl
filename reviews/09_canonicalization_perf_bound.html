Speed-of-Light Bound for the Proposed Canonicalization Core

Date: 2026-09-29 · Author: Claude (Opus 5.5) · Companion to: 08_canonicalization_literature_survey.md §10

Question. For the proposed core — encode a tensor monomial as a coloured graph, canonicalize by individualization–refinement (IR), collect terms by hashing — what is the best achievable time per term on a generic desktop CPU and a basic discrete GPU, given clock speed, cache, memory bandwidth and latency?

Status of the numbers. Two kinds of statement appear below. Floors in §3 are genuine lower bounds for any algorithm. Everything from §4 on is a model lower bound for this algorithm: it counts the minimum plausible work of an ideal IR implementation (perfect pruning, minimal instruction count per primitive) and divides by the hardware's peak sustainable rates. Real implementations can only be slower. The model script is 09_probes/bound.py; every table is generated by it.

  1. The CPU core is compute-bound, not memory-bound. The per-instance working set is about 80n bytes (≤ 3 KB), which fits in L1 many times over. The memory floor for streaming terms and inserting into the collection hash table is 4–6 ns per term on 8 cores, below the compute floor in every case — provided hash inserts are batched so that about 16 cache misses per core are in flight. A naive dependent-probe insert costs one full DRAM latency (80 ns) per term per core, which would double case A.
  2. Branch mispredictions are about half of the practical floor. The "ideal" column assumes branch-free refinement; the "practical" column charges 0.5 mispredicts per cell split. Branch-free refinement (bitset colour classes for ≤ 128 slots) is the largest single lever.
  3. Symmetric products pay for search, and the cost grows as n2. For k identical factors the ideal IR search costs Θ(k(V+E)), i.e. Θ(n2) when k∝n. That matches the ≈ n2 scaling SeQuant measured (survey §3). Riem8 costs 6.2× Riem3 in total work, 2.3× per slot.
  4. A basic GPU only wins if terms never cross PCIe. On-device floors are 0.7–35 ns per term, but the PCIe 4.0 ×8 transfer floor alone is 10–22 ns per term — comparable to the 8-core CPU for low-search terms. Offloading canonicalization alone buys at most 2–4× on B and C and nothing on A. The GPU case only becomes compelling when term generation, canonicalization and collection all stay on the device. For search-heavy terms the answer hinges on the unmeasured SIMT efficiency η.
  5. Current TensorGR is roughly 500–1000× above the practical floor. Measured: 438 µs per Riem3 canonicalization and 1.64 ms per Riem4 on this laptop (§9).

2. Instance model and graph encoding

A tensor monomial has m factors, n index slots, d dummy pairs and f free indices, so n=2d+f. Let k be the size of the largest set of identical, mutually exchangeable factors.

The encoding follows SeQuant (survey §3): one vertex per tensor core, per slot, and per index (a dummy pair is one index vertex joined to two slots), plus g "bundle" gadget vertices encoding slot symmetries (a Riemann tensor uses 3: two antisymmetric pairs and a pair-exchange bundle). Every slot has one edge to its index and one edge to its bundle or core, and every bundle has one edge to its parent:

V=m+n+d+f+g,E=2n+g.

The per-instance working set is CSR adjacency plus about four partition arrays, roughly 4(V+1)+8E+16V≈80n bytes: 1–3 KB for the cases below, far inside L1.

3. Algorithm-independent floors

Any canonicalizer must read the input and write the output. With a packed encoding of 4 bytes per slot plus a 16-byte header, bterm=4n+16 bytes. On one core this costs at least n/(ιf) — under 3 ns here, negligible. At scale, streaming terms in and out of DRAM costs

τstream≥2btermB,

which is 1.8–4.1 ns per term for n=12–32. This is the only rigorous floor; everything after it is specific to the IR algorithm.

4. Work model for ideal IR

Counts are in µops — the minimum plausible for each primitive.

Graph construction. Decode the input and build CSR adjacency:

Wbuild=4n+2E.

One full colour refinement. Each of the 2E adjacency entries must be touched at least once: load the neighbour, load its colour, increment a count, compare — about 4 µops. Re-bucketing each vertex costs about 6 µops:

Wref=4⋅2E+6V=8E+6V.

This is a lower bound per refinement: Hopcroft-style refinement is O((V+E)logV) in the worst case, and nauty/Traces also maintain invariant hashes.

Leaf and output. Relabelling by the discrete partition and forming or comparing the certificate costs Wleaf=3(V+E). Emitting canonical indices and the sign costs Wout=2n.

Search for k identical factors. The factors are permuted by Sk.

  • The first path individualizes k−1 factors (the last is forced), i.e. k−1 refinements.
  • To prove the canonical choice, the search must discover generators of Sk. With ideal orbit pruning, working upward from the deepest level, depth i needs one sibling explored down to a leaf, k−i individualizations, yielding the adjacent transposition (i,i+1). Those k−1 Coxeter generators generate Sk and complete every orbit.

The number of individualizations is therefore

Nind=(k−1)+∑i=1k−1(k−i)=(k−1)(k+2)2.

An incremental refinement after individualizing one factor touches roughly that factor's share of the graph, Wref/k. Each discovered generator also needs a leaf and a verification pass of 2(V+E) — mandatory if certificates are emitted — and a sign-character evaluation of n µops. So

Wsearch=NindWrefk+(k−1)(Wleaf+2(V+E))+(k−1)n.

Total and scaling:

W=Wbuild+Wref+Wleaf+Wout+Wsearch.

Since Nind/k≈(k+2)/2, Wsearch=Θ(k(V+E)). For products of Riemann tensors n=4k and V,E=Θ(n), so W=Θ(n2).

5. Single-core latency bound

Three limits apply: µop throughput, the dependent-load critical path, and branch mispredictions. Refinement proceeds in rounds, and each round's edge scans are independent, so out-of-order execution overlaps them. The critical path is therefore about 3 rounds per individualization, each a chain of 4 dependent L1 loads:

Clat=3(1+Nind)⋅4ℓ1.

With S=V+NindV/k cell splits:

t1ideal=max(W/ι,Clat)f,t1prac=max(W/ι+pbS,Clat)f.

The latency path is never binding here: for case D it is 2,160 cycles against 4,447 cycles of µop throughput. Cache misses are absent because the working set is L1-resident.

6. Multi-core throughput bound (canonicalize and collect)

Terms are independent, so work parallelizes across terms (the parallel study in survey §12). Per term, in aggregate over P cores:

τCPU=max(t1P,2bterm+2⋅64B,tmemPM).
  • The second term streams terms and moves one 64-byte hash-table line in and out per insert.
  • The third term is the latency floor for random hash-table inserts when the table exceeds L3 (about 107 distinct terms), with M misses in flight per core: 80/(8⋅16)=0.63 ns.
  • Without batching or prefetching, a dependent insert costs tmem/P=10 ns per term — as much as the entire canonicalization of case A.

7. GPU bound

On-device floor. Let η be the SIMT efficiency: the fraction of lane-slots doing useful work under warp divergence when a warp cooperatively refines one instance. Assume η=0.25 for low-search terms and 0.1 for search-heavy ones; this is the key unmeasured parameter. Per term:

τdev=max(WηRint,2bterm+64BGPU,12(1+Nind)ℓshfGPUNconc),

with Nconc=NSM⋅min(48,⌊100KB/80n⌋) concurrent instances held in shared memory.

Offload floor. If terms are produced on the CPU they must cross PCIe both ways. With transfers fully overlapped:

τoffload=max(τdev,2btermBPCIe).

11. What is and is not established

  • Rigorous: the I/O floor (§3). Model lower bounds for this algorithm: §4–§8, conditional on the µop counts per primitive and the peak rates in §1.
  • Not modelled:
    • Failed search branches (the model assumes perfect pruning).
    • Non-Sk symmetry groups: block symmetries, groups acting on pairs.
    • Multi-term (Bianchi) reduction, which is a separate linear-algebra layer.
    • Certificate serialization.
    • SMT and E-cores.
  • Most uncertain parameters:
    • The GPU SIMT efficiency η. The parallel study notes that realised GPU speed-ups for related irregular graph-canonical-form workloads have been ≤ 9×, and that others' reports are "too optimistic".
    • The sustained ι for refinement code.
    • The mispredict rate p.
  • What to benchmark first:

    1. A branch-free bitset refinement kernel on cases A–D against this table.

    2. The fraction of real terms (bench_12, golden masters) where refinement alone yields a discrete partition, i.e. Nind=0.

    3. Batched versus naive hash insertion at 107 distinct terms.
